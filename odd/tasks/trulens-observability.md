## Specs

S1. Improve the live workflow presentation requested by the user: "si quiero mostrar animaciones reales de buscando, escribiendo, validando, reemplazando respuesta, si me gustara que se mejorase visualmente". Acceptance: the UI reports real stage starts and completions for retrieval, generation, output validation, telemetry, and retry replacement; it introduces no fake delays or fabricated provider progress; failures retain the active stage and safe `st.error` behavior.

S2. Add the requested compact status information near the input: "generan la barra de estado en el cuadro de entrada con el modelo que se usa, la intencidad, si es higt, low, medium o lo que le modelo que se use disponga, tambine lokens consumidos y entre parentecis el porcentaje de la barra de contexto." Acceptance: a compact native Streamlit strip appears immediately above the chat input and shows the selected model, only provider-supported inference settings, last-response input/output tokens, and context utilization when a verified model context limit is configured; unsupported intensity or unknown context capacity is labeled unavailable rather than inferred.

S3. Implement the requested Snowflake observability outcome: "busca en la docuemntacion de snowflake para implementar trulens para la observabilidad , trazabilidad, y performaces del modelo." Acceptance: TruLens 2.1.2+ records OpenTelemetry-style traces for the custom Cortex Search + `AI_COMPLETE` RAG flow, including root, retrieval, and generation spans; Snowflake token/cost and per-span latency evidence is queryable through AI Observability; the integration follows current official Snowflake documentation.

S4. Keep TruLens inside the existing application architecture. `TruApp` is an SDK recorder/registration wrapper around the existing Sof~IA application, not a second user-facing application. The Snowflake `External Agent` is a governed metadata object representing this externally implemented custom RAG application; application code continues to run in this repository and traces/scores are stored in `SNOWFLAKE.LOCAL.AI_OBSERVABILITY_EVENTS`. Acceptance: domain and application policy remain free of TruLens/Snowflake imports; infrastructure/composition adapters own instrumentation, connector setup, registration, and failure isolation.

S5. Separate production tracing from evaluation. Acceptance: online requests record traces and performance metadata without running LLM judges synchronously; groundedness, context relevance, answer relevance, coherence, and optional correctness run through named batch datasets/runs; evaluation cost and failure do not block chat responses.

S6. Preserve least privilege and data governance. Acceptance: setup documents `SNOWFLAKE.CORTEX_USER`, `CREATE EXTERNAL AGENT`, External Agent `USAGE`, `CREATE TASK`, `EXECUTE TASK`, and `USE AI FUNCTIONS`; unredacted observability access is not granted by default; prompts, retrieved context, and responses are treated as potentially sensitive; credentials remain in Streamlit secrets/environment only.

S7. Assumption: no live Snowflake account mutation, privilege grant, External Agent registration, task creation, or paid evaluation run is authorized yet. Local implementation and fake-based tests may proceed in the next session; any live Snowflake operation requires explicit destination, operation, and credential/session authorization.

S8. Verification must cover behavior and architecture. Acceptance: tests prove truthful stage transitions, retry replacement, unknown/supported model metadata, token/context calculations, no domain/application dependency on TruLens, trace attribute mapping, connector failure isolation, and unchanged chat behavior; Ruff, mypy, the full pytest suite, Streamlit Agent API, and one named high-risk independent verifier pass before completion.
