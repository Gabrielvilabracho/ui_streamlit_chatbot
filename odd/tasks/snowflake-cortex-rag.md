# Snowflake Cortex RAG with Streamlit
Objective: build a production-oriented RAG chatbot using Clean Architecture, Snowflake Cortex Search/AI_COMPLETE, and Streamlit, styled from the CONTAVIA semantic palette.
Branch: `feature/snowflake-cortex-rag` · Delivery: `ask-on-risk` → `stacked-to-main` (forecast: ~1,000 authored lines) · Test runner: `pytest`

## Specs

S1. Implement the requested system outcome: "busca en snowflake, streamlit, con sus skills y docuemntacion para generar una sistema RAG utilizando Clean Architecture, Snowflake Cortex y Streamlit". Acceptance: the repository contains a runnable Streamlit application, a Snowflake-backed RAG path, and documented setup; current official Streamlit and Snowflake documentation is used as implementation evidence.

S2. Preserve strict architectural separation: "El código debe estar estrictamente modularizado para separar la UI de la base de datos y facilitar la inyección de guardarraíles y observabilidad." Acceptance: domain and application code do not import Streamlit or concrete Snowflake SDK classes; infrastructure implements application ports; UI receives dependencies from a composition root.

S3. Build the requested UI regions: "barra lateral (sidebar), Cabecera (Onboarding), Área de Chat, Barra de Controles (Footer del mensaje): Botones de Copiar, Reintentar, Feedback (st.feedback) y un plugin visual pasivo con el conteo de tokens (Input/Output) y latencia., Área de Input". Acceptance: every assistant response renders copy, retry, feedback, token counts, latency, and input controls with stable widget keys.

S4. Integrate sources, controls, and safe errors exactly as requested: "Debajo de la generación de respuesta, renderiza el st.expander con las fuentes. Usa st.columns para maquetar la fila de controles: botón de copiar, reintentar, widget de feedback y el plugin de visualización de tokens. Añade bloques try/except para que los timeouts se muestren como alertas (st.error) en lugar de romper la aplicación." Acceptance: source citations render below responses; controls use columns; timeout failures render through `st.error` without terminating the app.

S5. Implement the requested Streamlit flow: "Programa el archivo app.py. Implementa la barra lateral para el selector de modelos. Crea el bucle del historial de chat. Dentro de la llamada al asistente, implementa el st.status integrando un st.checkbox por cada paso del orquestador para simular la checklist de ejecución." Acceptance: `app.py` is the composition root, model selection and chat history work through session state, and each orchestration step appears as a disabled checkbox inside `st.status`.

S6. Place the system prompt as a central rule: "El System Prompt debe alojarse en la Capa de Dominio (Domain) o en la Capa de Aplicación (Application), comportándose como una regla central del negocio o una plantilla estandarizada." Acceptance: the prompt is versioned in domain/application code and injected into the orchestration service rather than declared in the UI or Snowflake adapter.

S7. Apply the requested visual system: "utiliza /Users/gabrielvilabracho/TDHA\ OS/projects/CONTAVIA/Assets/semantic-palette-reference.html para establecer la semantic palette refenrecia y typologia para la aplicacion." Acceptance: Streamlit theme/CSS uses the reference palette (`#17ABB5`, `#1AAEB7`, `#CFEFF0`, `#EAF5F7`, `#222222`, `#F2F2F2`, `#FFFFFF`, retained near-white surfaces) and the documented grotesque typography stack.

S8. Assumption: no live Snowflake account, credentials, database, schema, or Cortex Search service was authorized for this session. Acceptance: implementation is locally testable with fakes, loads secrets only from Streamlit secrets/environment, includes SQL/setup documentation, and performs no remote Snowflake operation during verification.
